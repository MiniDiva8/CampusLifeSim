# 架构

项目分为五层：

1. JSON 内容层：地点、NPC、事件、AI 建议与结局。
2. 核心规则层：时间、会话状态、事件条件与效果。
3. 服务层：内容加载校验、自动存档、设置持久化。
4. 表现层：主菜单、角色初始化、地图、事件、暂停、设置和结局。
5. 验证层：无界面规则测试、内容校验和 Windows 构建检查。

界面只能通过明确接口修改游戏状态，JSON 只描述受控条件和效果，不执行脚本。

`ArchiveMainMenuView` 和 `RouteSetupView` 是两个全画布纸质界面。前者只读取存档摘要并连接新建、继续、设置、许可和退出回调；后者把玩家输入转换为姓名、路线 ID 和难度 ID，再交回 `main.gd` 创建存档。它们不直接修改运行中的游戏状态。`RouteRules` 是路线说明与结算规则的唯一来源，统一处理学习、项目、关系、行动压力和事件优先级，事件选项预览也调用同一规则，避免界面文案与实际结果分离。

`DifficultyRules` 在 `EventEngine` 应用效果前统一调整数值，确保事件 JSON 保持单一基础数值。`GameSession` 只保存难度 ID，不复制倍率配置；旧存档自动回退到简易规则。

`DecisionRules` 统一定义固定事件与自主行动的时间成本、阶段承诺、四类债务和考试/展示质量判定。`EventEngine` 在推进较长行动前查询下一项未触发固定日程，避免压缩点击数后跳过主线。`GameSession` schema 2 保存承诺进度、债务、选择计数、延迟因果来源与里程碑结果，并兼容 schema 1 存档。

`BackgroundCatalog` 除了随机选择照片，还从清单提供真实场景名称、活动文本、固定事件地点语义和 EXIF 方向。`OrientedPhotoRect` 不改写原 JPEG，而是在显示层旋转画面。

`AdaptiveSceneView` 将照片和交互内容分成两个稳定区域。它依据旋转后的原图宽高比选择 474、652 或 704 像素的照片舞台，竖图与横图都保持完整比例；事件卡不再覆盖照片，也不再创建同图模糊铺底。事件、地点行动、结算与压力危机共用这一组件，按钮回调仍由 `main.gd` 连接到既有规则层。

表现层的共享视觉基础由 `GlassPanel`、`neo_glass.gdshader` 与 `GlassHoverController` 组成。`GlassPanel` 只对面板背后的屏幕内容做一次低采样模糊、色调混合、饱和度控制和边缘高光，文字与按钮内容位于独立的清晰层；圆角遮罩使用像素导数计算，不绑定 1280×720。`GlassHoverController` 为按钮提供鼠标位置聚光、焦点描边、按压缩放与悬停抬升，并读取“减少界面动效”设置。地图背景的渐变、柔光和网格全部由 Godot 绘制，不依赖外部纹理。

为避免多重屏幕取样造成兼容性和性能问题，只有主信息面板使用真实屏幕毛玻璃；面板内部的数值卡、选择卡和进度条使用半透明 `StyleBoxFlat` 模拟玻璃层次。校园实景照片、长曝光压力照片和道路照片从不经过模糊材质，继续使用 `OrientedPhotoRect` 保持原始纹理、比例与 EXIF 显示方向。

原图读取采用“即时反馈 + 有界缓存 + 后台准备”。`main.gd` 在一次场景数据构建中只取得一次 `Texture2D`，并直接传给宽高比判断和 `AdaptiveSceneView`，不再为同一画面重复调用 `load()`。最近使用的四张纹理由 LRU 缓存保留；道路、目的地、下一幕固定事件和压力危机照片通过 `ResourceLoader.load_threaded_request()` 并行准备。缓存上限避免 65 张高分辨率照片全部驻留内存。事件 JSON 的 `delayed` 仍只表示未来时段的数值后果，不包含真实等待计时器。

选项回调先禁用当前按钮、切换忙碌光标并显示“正在结算”徽标，然后在下一帧应用规则和重建结果界面。这使磁盘或纹理首次准备偶尔较慢时，玩家仍能在点击当帧得到明确反馈，同时阻止双击重复结算。

`AudioDirector` 是独立于玩法状态的表现服务。按钮通过 `audio_cue` 元数据声明“确认、返回、选择、地点进入”等语义，而不是引用具体音频文件；服务负责自动发现按钮、并发声部限制、重复触发冷却、轻微音高变体、总线分发和暂停期间仍可工作的总线淡入淡出。声音可在以后替换为有许可证记录的 WAV 文件，而无需重写 UI 回调。

音频路由采用 `UI/Event/Stress → SFX → Master`、`Music → Master`、`Ambience → Master`。设置存档只保存 Master、Music、SFX、Ambience 四个用户音量和压力音效开关；Master 最后一层使用限制器避免短音叠加削波。

`AmbientSoundController` 以稳定的 `transition_to(context, period, fade, stress)` 接口管理校园声景。主菜单、校园、道路和六个地点分别对应语义上下文，早晨至下午、晚上、深夜映射为 day/evening/night 三个声音时段。控制器使用双播放器交叉淡化，路途开始时预热目的地循环，避免抵达时加载停顿。

当前循环由固定种子的滤波噪声与短时包络原创生成，包含风声、脚步、翻页、键盘、设备风扇、餐具、球声和夜间虫声；高压身体反馈通过独立 Stress 总线播放。以后可以把上下文对应的流替换为实地录音，不改变主流程或存档结构。
