# 事件选择界面视觉方向

## 范围与模式

- 范围：`scripts/ui/editorial_event_view.gd`，仅替换事件选择界面。
- 模式：Operate + Experience。玩家必须快速理解状态和选择，同时让校园照片成为体验主体。
- 本轮不改：主菜单、校园地图、设置、暂停、结果和结局界面。

## 视觉论点

把一次校园事件设计成“正在发生的校园摄影报道”，而不是把照片塞进黑色游戏面板。

## 内容计划

1. 全画布原始校园照片；
2. 页边日期、地点与三项核心状态；
3. 事件标题和短叙事；
4. 无边框的编号选择列表；
5. 自动存档、时段消耗和当日时段刻度。

## 交互论点

- 进入时照片先稳定出现，标题和选择分别以 160–240ms 的轻微位移进入。
- 悬停或键盘聚焦只移动文字、显露山大红侧标并延长底部细线，不抬升整块矩形。
- 点击立即锁定选项并显示结算反馈，不增加人为等待。

## 方向契约

**THESIS：** 一张校园照片就是整个事件现场；拒绝顶部仪表盘、左右卡片和按钮网格。

**OWN-WORLD：** 原图、石材灰白、雾蓝、石墨字与单一山大红批注；控件使用页边信息、细线和编号，不使用玻璃卡片。

**STORY：** 玩家先认出真实地点，再理解这次期末事件，最后比较三个会改变进度与压力的行动。

**FIRST VIEWPORT：** 原图完整居中并占满可用画布；叙事在左下稳定区域，选择在右半部纵向排列，日期和状态贴近上边缘。
**FORM：** 校园纪实摄影 × 期末周编辑排版；采用构图稿 A 的左右张力，并吸收构图稿 B 的明亮石材色。方向由用户明确固定，因此没有执行 concept roll，seed 记为 `user-pinned/no-roll`。

## 构图参照

- 采用：`.impeccable/mocks/event-editorial-a.png`
- 光感参照：`.impeccable/mocks/event-editorial-b.png`
- 未采用：`.impeccable/mocks/event-editorial-c.png`，原因是整体压暗程度接近用户明确拒绝的深色界面。

构图稿是方向测试，不是需要逐像素复刻的最终截图。生成稿中的文字、照片和装饰不会作为运行时位图使用。

## 实现清单

| 可见元素 | 实现介质 | 说明 |
| --- | --- | --- |
| 校园场景 | 用户原始照片 | 继续从 `assets/backgrounds/` 加载；不压缩、不重编码 |
| 画布余白 | Godot `ColorRect` | 使用石材灰白，不使用纯黑 |
| 局部可读性过渡 | Godot `GradientTexture2D` | 只在文字附近渐变，不形成矩形遮罩 |
| 标题、正文、状态 | Godot `Label` | 保持代码原生、可本地化 |
| 选择 | Godot `Button` + 原生子节点 | 正常态完全无框，使用编号、细线和文字层级 |
| 悬停与焦点 | GDScript Tween | 侧标显露、文本位移、细线延长 |
| 时段进度 | Godot 原生线与圆点 | 不使用卡片或胶囊 |
| 音效 | 现有 `AudioDirector` | 延续语义化 `choice` 提示音 |

## 验收条件

- 事件页没有纯黑背景、大型深色面板、玻璃卡片、状态胶囊和选项方框。
- 当前照片完整显示且保持原比例；不以生成图替换用户原图。
- 鼠标和键盘均能清楚识别当前选择。
- 1280×720 下三项选择无需滚动；长文本仍能安全换行。
- 点击回调继续在 150ms 内给出反馈。
